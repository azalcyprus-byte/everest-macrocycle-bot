# Everest Macrocycle Bot v12.4

Telegram-координатор Макроцикла №3. Версия v12.4 сохраняет рабочий утренний оркестратор v12.3 и добавляет управляемое обсуждение плана дня и первую реализацию агента фаз.

## Главное изменение

После заполнения трёх утренних чек-листов бот больше не выдаёт расписание немедленно. Через установленную задержку он открывает устойчивую планировочную сессию:

1. читает фактическое время подъёма из первого утреннего чек-листа и не спрашивает его повторно;
2. уточняет, был ли приём пищи и когда;
3. читает допущенные задачи из `05_Проекты_и_задачи`;
4. читает входящие задачи из `17_Входящие_задачи`, если вкладка уже создана;
5. спрашивает только недостающие задачи, ограничения и оценки времени;
6. агент фаз оценивает сон, энергию, ясность, остаточный Overheat/Irritation, хвост нагрузки, телесные сигналы и цену предыдущего дня;
7. при плохом состоянии агент может только предложить сокращение игры и/или study;
8. исходный покерный PLAN остаётся неизменным до явного ответа Андрея `сокращаем`;
9. после обсуждения бот показывает черновик и ждёт `утверждаю`;
10. состояние диалога сохраняется во вкладке `16_Журнал_действий` и восстанавливается после перезапуска Railway.

## Полномочия агента фаз

Агент фаз:

- не увеличивает игру или study;
- не меняет утверждённый PLAN автоматически;
- при нормальном состоянии сохраняет PLAN;
- при жёлтом или красном состоянии формирует обоснованное предложение о сокращении;
- применяет сокращённые часы в черновике только после явного APPROVAL;
- после определения покерной нагрузки оценивает резерв для дополнительных задач;
- при отклонении сокращения сохраняет исходный PLAN и обнуляет резерв дополнительных задач, чтобы не усиливать перегруз.

## Входящие задачи

Бот поддерживает вкладку `17_Входящие_задачи`. Если её ещё нет, планирование продолжается без падения и сообщает, что источник недоступен.

Минимально ожидаемые заголовки:

- `INBOX_ID`
- `Дата и время появления`
- `Исходная формулировка Андрея`
- `Нормализованная задача`
- `Срочность`
- `Дедлайн`
- `Жёсткое временное окно`
- `Оценка времени Андрея, ч`
- `Оценка времени системы, ч`
- `Что нужно уточнить`
- `Статус разбора`
- `Связанный Task ID из 05_Проекты_и_задачи`

Активно читаются статусы `Новое`, `Нужно уточнение`, `Готово к переносу`, `Отложено`. Неразобранная входящая запись не включается в утверждённый план автоматически.

## Новые команды

- `/planningstatus` — показать текущий этап планировочной сессии, ACTION_ID и повторить текущий вопрос или черновик.
- `/planningtest` — изолированно проверить чтение подъёма, approval-gate агента фаз, доступность вкладки 17 и сборку черновика. Рабочие таблицы и текущая сессия не изменяются.

Также действуют:

- `/hqstatus`
- `/morningstatus`
- `/morningcheck`
- `/morningtest`
- `/hqtest`
- `/hq <поручение>`
- обычное сообщение `Составь план на день`
- фраза `Доброе утро` для запуска утреннего оркестратора.

## Сценарий разговора

После готовности чек-листов бот спрашивает о питании. Пример ответов:

```text
Нет, ещё не ел.
```

```text
Нужно забрать документы и позвонить в банк. Закончить работу до 18:00.
```

```text
Документы — около 40 минут, звонок — не знаю.
```

При предложении агента фаз:

```text
сокращаем
```

или:

```text
оставляем исходный план
```

После просмотра черновика:

```text
утверждаю
```

## Развёртывание через GitHub и Railway

1. В подключённом GitHub-репозитории заменить корневой `bot.py` файлом из этого пакета.
2. При необходимости заменить `requirements.txt`.
3. Сделать commit и push в ветку, подключённую к Railway.
4. Дождаться `Deployment successful`.
5. Отправить `/hqstatus`; ожидаемая версия — `v12.4`, формы — `3/3`.
6. Отправить `/planningtest`; итог должен быть `PASS`.
7. Отправить обычным текстом `Составь план на день`. Бот должен начать с вопроса о приёме пищи, а не выдать финальное расписание.

## Текущие границы

- Утверждение черновика фиксируется в журнале действий, но финальная запись всех блоков в `10_План_факт_дня` и Google Calendar ещё не подключена.
- Входящие задачи читаются и используются для уточняющих вопросов; перенос полноценной карточки в `05_Проекты_и_задачи` выполняет управляющий проекта, а не эта версия бота.
- Агент питания пока регулирует время приёмов пищи, но не формирует меню.
- Бот не выдумывает отсутствующие дедлайны, оценки времени или обязательность задач.
