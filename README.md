# Everest Macrocycle Bot

Закрытый Telegram-бот для системы Macrocycle #3.

## Команды

- `/start` — проверка бота и авторизации.
- `/sheet` — проверка Google Sheets.
- `/readtest` — чтение рабочих данных.
- `/writetest` — безопасный тест записи в план-факт.
- `/calendartest` — чтение календаря и поиск пересечений.
- `/eventtest` — создание, изменение и удаление тестового события.
- `/schedulertest ЧЧ:ММ` — устойчивое плановое задание.
- `/schedulerstatus` — статусы планировщика.
- `/journaltest` — журналирование действия и блокировка повторного исполнения.
- `/journalstatus` — последние записи журнала.
- `/dayplantest` — основной тест: прочитать план дня и три утренних чек-листа, определить допуск онлайн-сессии и отправить отдельное сообщение координатора.
- `/dayplantest repeat` — повторный прогон в тот же день с отдельными тестовыми ID.
- `/fullplantest` — собрать полный план дня: игра, работа над игрой, приёмы пищи и допущенные задачи.
- `/fullplantest repeat` — повторный прогон полного плана.
- `/dayplancleanup CONFIRM` — удалить тестовые записи `/dayplantest` и `/fullplantest` из планировщика и журнала действий.
- `/notifytest ЧЧ:ММ` — старый тест уведомления в памяти процесса.
- `/buttonstest` — тестовая карточка с кнопками.

## Блок №25: журнал действий и идемпотентность

При первом вызове бот создаёт вкладку `16_Журнал_действий`.

Каждое действие, выполняемое через обязательный исполнитель
`execute_action_once`, получает:

- уникальный `ACTION_ID`;
- `IDEMPOTENCY_KEY`;
- операцию, тип и ID объекта;
- источник и цель;
- хеш и JSON входных данных;
- статус `STARTED`, `SUCCEEDED` или `FAILED`;
- JSON результата;
- время начала и завершения;
- количество заблокированных дублей;
- ошибку, исполнителя и системную проверку.

### Механизм защиты

1. До побочного эффекта создаётся строка со статусом `STARTED`.
2. Ключ идемпотентности проверяется под межпоточным lock.
3. Если ключ уже существует, действие не выполняется.
4. В существующей строке увеличивается счётчик дублей.
5. После успеха строка переводится в `SUCCEEDED`.
6. После ошибки — в `FAILED`.
7. Состояние `STARTED` также блокирует повтор, что безопаснее
   повторного исполнения при неопределённом результате.

### Тест `/journaltest`

Команда:

1. регистрирует техническую запись до исполнения;
2. один раз записывает маркер в `10_План_факт_дня!R503`;
3. читает маркер и проверяет формулы;
4. очищает ячейку;
5. повторяет тот же запрос с тем же ключом;
6. проверяет, что повтор заблокирован, а действие выполнилось ровно один раз;
7. оставляет одну итоговую строку журнала как доказательство теста.

Рабочие показатели дня не изменяются.

## Переменные окружения

- `BOT_TOKEN`
- `TELEGRAM_USER_ID`
- `GOOGLE_SERVICE_ACCOUNT_JSON`
- `GOOGLE_SHEET_ID`
- `GOOGLE_CALENDAR_ID` — необязательно; по умолчанию `azalcyprus@gmail.com`.
- `PORT` — необязательно, по умолчанию `8000`.
- `ONLINE_GAME_START` — начало онлайн-игры для расчёта сокращённой сессии; по умолчанию `09:00`.
- `DAY_PLAN_TEST_DELIVERY_DELAY_SECONDS` — задержка отдельного тестового сообщения; по умолчанию `10`.
- `SLEEP_QUALITY_RED_MAX` — верхняя граница красного статуса по качеству сна; по умолчанию `3.0`.
- `SLEEP_QUALITY_YELLOW_MAX` — верхняя граница жёлтого статуса по качеству сна; по умолчанию `5.4`.
- `STUDY_AFTER_GAME_GAP_MINUTES` — пауза между игрой и работой над игрой; по умолчанию `90`.
- `MEAL_BLOCK_MINUTES` — техническая длительность приёма пищи для распределения блоков; по умолчанию `20`.
- `FULL_PLAN_DAY_END` — конец окна для дополнительных задач; по умолчанию `20:10`.

## Обновление v11.0: тест утреннего планирования

Команда `/dayplantest` использует текущую дату по Москве и читает:

- `Утро`;
- `Утро 60 мин`;
- `Утро 90 мин`;
- план игры и study из `02_День`.

Бот проверяет наличие всех трёх чек-листов и оценивает:

- ясность мышления;
- восприятие информации;
- устойчивость внимания;
- остаточную перегрузку и раздражение;
- физическое восстановление;
- сонливость;
- запас энергии;
- качество сна `0–10` из `02_День`. Этот показатель уже учитывает продолжительность сна, скорость засыпания, ночные пробуждения, помехи и температуру.

Правило качества сна по умолчанию:

- `1,0–3,0` — `RED`, сегодня лучше не играть;
- `3,1–5,4` — `YELLOW`, сессия сокращается;
- `5,5–10,0` — качество сна само по себе не ограничивает игру.

Результат:

- `GREEN` — сессия разрешена полностью;
- `YELLOW` — сессия сокращается до двух третей планового объёма с округлением до 30 минут;
- `RED` — штаб рекомендует не играть;
- `INCOMPLETE` — решение не принимается, пока не найдены все данные;
- `NO_GAME` — по плану онлайн-игры нет.

Тестовое сообщение сохраняется во вкладке `15_Планировщик`, действие фиксируется во вкладке `16_Журнал_действий`, после чего сообщение доставляется отдельным Telegram-сообщением. Основной прогон за дату защищён от повторного запуска.

Это обновление не формирует меню, не назначает число столов и не создаёт полный план дня: эти параметры не выдумываются до утверждения соответствующих правил.


## Обновление v11.1: качество сна

`/dayplantest` теперь обязательно читает `Качество сна, 0-10` из строки текущего дня на вкладке `02_День`. Если показатель отсутствует, решение получает статус `INCOMPLETE`, а бот не выдаёт ложный допуск. Пороговые значения можно изменить переменными окружения, но красная граница должна быть ниже жёлтой.


## Обновление v11.2: полный план дня

Команда `/fullplantest` использует уже принятое решение по игровой сессии и формирует конкретное расписание.

Источники:

- план игры, работы над игрой, фаза и тип дня — `02_День`;
- времена приёмов пищи — последний существующий шаблон того же типа дня в `10_План_факт_дня`;
- уже назначенные на сегодня блоки — `10_План_факт_дня`;
- дополнительные задачи — `05_Проекты_и_задачи`.

Дополнительная задача включается только если:

- статус задачи активный;
- `Статус допуска = Готово`;
- нет блокера;
- тип дня и фаза входят в допустимые;
- задача помещается в свободное окно до `FULL_PLAN_DAY_END`.

Правила распределения:

- онлайн-игра начинается в `ONLINE_GAME_START`;
- при `YELLOW` используется сокращённая продолжительность из решения штаба;
- после игры ставится окно восстановления `STUDY_AFTER_GAME_GAP_MINUTES`;
- работа над игрой сохраняет плановый объём;
- приём пищи не ставится внутрь непрерывного учебного блока: блок автоматически разделяется на две части;
- при `RED` онлайн-игра и работа над игрой в тестовом плане не назначаются;
- неподтверждённые задачи бот не вставляет самовольно.

Команда не записывает рабочий план в `10_План_факт_дня` и не меняет Google Calendar. Она только формирует тестовое Telegram-сообщение через устойчивый планировщик.
