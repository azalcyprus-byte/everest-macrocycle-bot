# Everest — мониторинг состояния Алексея Жукова

**Статус:** отдельный модуль в PR. В рабочей среде он выключен по умолчанию, пока не завершена настройка.

## Действующая архитектура

- Google Forms остаются прежними: ответы на вкладках «Утро — ответы» и «После игры — ответы».
- Google Apps Script (файл apps_script/ZhukovEvents.gs) записывает факт новой отправки в «Everest_Алексей_события».
- Существующий Everest Telegram-бот каждые 5 минут проверяет Sheets и формирует события.
- Отдельная вкладка «Everest_Алексей_мониторинг» хранит активацию, пропуски, аналитику, статус доставки и подтверждённые решения куратора.
- Анализ и уведомления отправляются только в чат куратора. Личные чек-листы куратора и напоминания Алексею не изменяются.

## Перед первым включением

1. Сервисному аккаунту из GOOGLE_SERVICE_ACCOUNT_JSON нужны права **Редактор** на таблицу Алексея. Старых прав «Читатель» для создания журнала недостаточно.
2. В таблице открыть Extensions → Apps Script. В существующем файле ZhukovEvents.gs использовать актуальный код apps_script/ZhukovEvents.gs. Если installAlexeyFormTrigger уже выполнялась, повторно запускать её не требуется. Выполнить вручную testAlexeyEventJournal: она проверяет триггер, временно пишет __TEST_ONLY__ в «Everest_Алексей_события», проверяет запись и удаляет только собственную строку. **Не заполнять форму Алексея тестовыми данными** — это исказит его статистику. Срабатывание настоящего триггера следует подтвердить после следующего реального ответа Алексея.
3. Уточнить Telegram ID приватного чата куратора; он не должен совпадать с ID Алексея.
4. Установить правильный IANA-часовой пояс Алексея (ZHUKOV_TIMEZONE). Без ZHUKOV_MONITOR_ANCHOR_LOCAL первая утренняя анкета, полученная **после даты активации**, автоматически задаст опорную точку; архивные анкеты не участвуют. Если нужен особый заранее согласованный опорный момент, задать ZHUKOV_MONITOR_ANCHOR_LOCAL явно. Часовой пояс исходной таблицы — Asia/Shanghai.
5. Проверить настройки Railway и включить мониторинг только после теста.

## Railway environment

Существующие переменные не удалять. Новые переменные:

    ZHUKOV_MONITOR_ENABLED=false
    ZHUKOV_CURATOR_CHAT_ID=<ID чата куратора>
    ZHUKOV_SHEET_TIMEZONE=Asia/Shanghai
    ZHUKOV_TIMEZONE=<текущий IANA часовой пояс Алексея>
    ZHUKOV_MONITOR_ANCHOR_LOCAL=<YYYY-MM-DDTHH:MM:SS первого опорного отчёта>
    ZHUKOV_MONITOR_EVENT_MODE=script
    ZHUKOV_MACROCYCLE_START_DATE=<YYYY-MM-DD, если известно>
    ZHUKOV_MACROCYCLE_PHASE=<текущая фаза, если известно>
    ZHUKOV_PRIORITY_TOURNAMENTS=<приоритетные турниры, если известны>
    ZHUKOV_MONITOR_OPENAI_ENABLED=false
    ZHUKOV_MONITOR_OPENAI_MODEL=gpt-4.1-mini

В режиме EVENT_MODE=script новые аналитические сводки инициируются событиями Apps Script. При отсутствии триггера временно использовать EVENT_MODE=poll для чтения непосредственно ответов; контроль пропусков работает в обоих режимах.

Опционально OPENAI_API_KEY и ZHUKOV_MONITOR_OPENAI_ENABLED=true включают дополнительную AI-гипотезу. По умолчанию сведения Алексея во внешнюю модель не отправляются. При отключении/сбое OpenAI контроль пропусков и базовая аналитика работают.

## Контроль времени и защита от дублей

Первый отчёт 01.10 в 08:00 (локальное время) → проверка отчёта за 02.10 в 14:00, затем 03.10 в 14:00 и далее. Контрольная точка основана на календарном локальном времени, не на времени позднего ответа. Новый часовой пояс Алексея необходимо указать в ZHUKOV_TIMEZONE при смене страны.

Фактическая отправка может быть позднее контрольной минуты на срок до ~5 минут из-за периодического запуска бота.

Мониторинг при первом включении фиксирует дату активации и не рассылает исторические пропуски. Каждому пропуску соответствует один постоянный ключ, записываемый до Telegram-отправки. Неопределённая ошибка доставки помечается REVIEW, без автоматической повторной отправки, во избежание дублей. Рассчитано на один работающий экземпляр бота.

## Сводка

ФАКТ → НАБЛЮДЕНИЕ → ГИПОТЕЗА → ПРЕДЛАГАЕМОЕ РЕШЕНИЕ.

Данные за 3 дня, 7 дней и с начала макроцикла (если известна дата начала), иначе за всю имеющуюся историю. Оцениваются сонливость, окно сна (не измеренная продолжительность фактического сна), внимание, замедление простых решений, часы игры, конкретные сбои и автоматизм, изменение внимания и анализа между первой и последней третями сессии, пары «длинная игра → следующее утро» и «отдых → следующее утро». Нет рейтинга 0–100. Сон более 8 часов сам по себе не снижает нагрузку. Гипотезы не считаются доказанными причинами.

Решение куратора добавляется в историю отдельной строкой командой, доступной только владельцу:

    /zhukovdecision 2026-10-20 Оставить согласованный план и проверять внимание на перерывах

## Проверки

GitHub Actions выполняет компиляцию и тесты: расписание 30+24, дедупликация, поздние анкеты, границы времени, отдельная доставка куратору и Apps Script event mode.

Перед продуктивным включением дополнительно проверить безопасный ручной testAlexeyEventJournal (без внесения ответов в форму), права Editor, затем после **следующей подлинной отправки анкеты Алексеем** — живое событие Apps Script. Реальную доставку только в чат куратора, запись решения и отсутствие дублирования после перезапуска проверить отдельно. Последнюю проверку GitHub CI не заменяет.

**GitHub PR не устанавливает Apps Script триггер и не меняет Railway Variables.** Эти операции требуют авторизации в соответствующих сервисах.
